# Black-box QA harness cases (extra/qa) that fail because of known, unfixed
# bugs: <harness> <case>  <ticket>
# <harness> is the script name without .py, <case> the case it reports (a
# mode, or the harness's single case name), or * for all of its cases. The
# case may be a shell-style pattern ('*' also matches '/'), and a name
# without '/' also covers every '<name>/...' case. Multi-case harnesses name
# their cases '<mode>/...' (see nightly_stages.py); the rotation harnesses
# (s3_fault_sweep, disk_fault_sweep, network_fault_test, listener_fuzz_test,
# source_change_test, large_binlog_test, pull_load_test) run about once a week,
# so their known failures show up on those nights only.
# A sanitizer report is never covered by a pattern line (its reason names
# the report) unless the ticket text mentions the sanitizer.
# A failure listed here is reported as known; any other failure is NEW.
# Remove a line once its bug is fixed.
pull_heartbeat_test quiet_after_rotation  ticket 40 (PBS-113): no heartbeats while the replica waits in a new binlog that holds only the binlog magic, so it reconnects every replica_net_timeout
query_race_test list_next_to_pull  ticket 29: a query next to a writer fails stat()ing a .tmp file the writer renamed away
source_change_test */reset  ticket 25: RESET BINARY LOGS AND GTIDS on the source is not detected (the stored binlog.000001 no longer matches the source's)
source_change_test */identity  ticket 25: a different source server (new server_uuid) on the same address is not detected
source_change_test gtid/restart  ticket 6: pull aborts at storage.cpp:138 (incomplete_transaction_timestamps_ not empty in open_binlog) when it reconnects in GTID mode after the source restarted
large_binlog_test position/transaction_over_4gib  ticket 41 (PBS-114): the collector refuses a transaction of 4 GiB or more ("transaction length in the ... gtid log event is too large"), so fetch / pull stop at it for good
pull_load_test position/shutdown  ticket 43 (PBS-116): with the source idle, pull exits after SIGTERM only when its blocking read from the source times out (connection.read_timeout); clients stay connected until then
pull_soak_test position/log  ticket 45 (PBS-118): at info level pull logs every event it streams to every client ("generated binlog event packet", 89% of the lines) and every event it receives, so the log grows with event rate times clients (67 MB/h in a 15-minute trial with 5 clients)
pull_tls_test position/plain_refused_when_required  ticket 48: under require_secure_transport pull closes the connection of a plain client without an error packet, so the client sees only 'Lost connection to MySQL server during query' instead of ER_SECURE_TRANSPORT_REQUIRED (3159, 'Connections using insecure transport are prohibited'); pull keeps serving TLS clients
pull_gtid_test gtid/purged  ticket 20 (PBS-120): pull does not check a GTID-mode replica's set against the GTIDs its storage no longer has: after purge_binlogs a replica with an empty GTID set is streamed what is left (received :80-104 of :1-104, the SQL thread then fails on a missing table) instead of being refused with ER 1236 as a MySQL source does
pull_gtid_test gtid/ahead  ticket 20 (PBS-120): pull does not check a GTID-mode replica's set against the GTIDs it has: a replica with a GTID of the source's UUID beyond anything written (:1000000) is accepted and waits instead of being refused with ER 1236 ('the replica has more GTIDs than the source')
telemetry_test position/settings_in_storage  ticket 50: with instance.local_settings_path pointing at the storage directory, the instance_id file is created before the storage is opened, so on a fresh storage fetch, list and pull all fail with 'storage is not empty but does not contain metadata'
